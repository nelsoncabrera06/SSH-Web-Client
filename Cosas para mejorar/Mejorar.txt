Cosas para mejorar - SSH-Web-Client
(notas del 2026-08-04, proyecto personal, no urgente)

1. Sesion SSH global compartida
   Se usa una sola instancia de Client (var conn = new Client()) y variables
   globales (mistream, finalizar, ped) para TODOS los sockets conectados.
   Si dos pestanas o dos usuarios usan la app al mismo tiempo, las sesiones
   se pisan entre si. No es grave para uso personal en localhost, pero si en
   algun momento la usa mas de una persona/pestana a la vez, se rompe.

2. Sin autenticacion en la app web
   Cualquiera que llegue al puerto 8080 puede abrir una sesion SSH a
   cualquier host que indique. Aceptable en localhost, mas riesgoso si se
   expone a una red o a internet.

3. Sin HTTPS/TLS
   Las contrasenas viajan del navegador al server en texto plano (via
   socket.io sobre HTTP). Fine en localhost, no fine si esto sale de la
   maquina local.

4. [RESUELTO 2026-08-04] Codigo muerto en index.js
   Las rutas /banner y /password en Express guardaban req/res en variables
   globales (ped, resp) pero nunca se usaban despues. Se eliminaron esas
   rutas y las variables sin uso (pass, ped, resp, cam).

5. [RESUELTO 2026-08-04] package.json incompleto
   Faltaba "main", "scripts.start", licencia, y el nombre/descripcion
   seguian siendo los del tutorial original de socket.io. Se completo
   todo y ahora se puede levantar el server con "npm start".

6. [RESUELTO 2026-08-04] Terminal ilegible en la web
   La salida del shell remoto se volcaba cruda en un <pre>, mostrando los
   codigos de escape ANSI en vez de interpretarlos (colores, cursor, etc).
   Se reemplazo por xterm.js, que renderiza una terminal de verdad.

7. [RESUELTO 2026-08-04] Solo soportaba keyboard-interactive
   La app solo intentaba autenticarse con keyboard-interactive, asi que
   fallaba directo ("All configured authentication methods failed") contra
   cualquier server que no ofreciera ese metodo (la mayoria). Ahora soporta
   tambien password y publickey.

8. [RESUELTO 2026-08-04] Sin soporte de jump host
   No se podia llegar a hosts que solo son alcanzables via un jump host
   (ProxyCommand/ProxyJump en ~/.ssh/config). Ahora la app lee el
   ~/.ssh/config de la maquina en runtime (nada de esto se hardcodea en el
   codigo, para no subir infraestructura propia a este repo publico) y, si
   corresponde, salta primero por el jump host antes de conectar al destino.
